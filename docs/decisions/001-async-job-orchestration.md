# ADR 001: 과제를 비동기 작업 오케스트레이션 문제로 정의

## 상태

채택

## 배경

- 클라이언트는 서버에 이미지 처리 작업을 요청하지만 실제 처리는 외부 Mock Worker가 수행한다.
- Mock Worker는 응답 시간이 길고 안정성이 변동될 수 있다.
- 클라이언트는 작업의 상태, 결과, 목록을 조회할 수 있어야 한다.
- 중복 요청 처리, 상태 전이, 처리 보장 모델, 재시작 시 동작을 설명해야 한다.
- 따라서 이 과제의 핵심은 단순 API 프록시가 아니라 작업 수명주기를 안정적으로 관리하는 서버를 설계하는 것이다.

## 결정

- 이 과제는 동기 프록시 API가 아니라 비동기 작업 오케스트레이션 백엔드로 해석한다.
- 작업 접수와 실제 실행 완료를 분리하고, 완료 시점과 무관하게 조회 가능한 작업 레코드를 유지해야 한다.
- 이후 설계는 상태 전이, 중복 요청 처리, 실패 표현, 재시작 복구를 1급 설계 요소로 다뤄야 한다.
- 저장소, 스케줄링, 재시도 정책, 중복 판별 방식의 구체적인 선택은 후속 ADR에서 결정한다.

## 영향

- 장점:
  - 요구사항 중심으로 설계 범위를 고정할 수 있다.
  - 외부 워커 지연에 종속되는 동기식 설계를 피할 수 있다.
  - 후속 ADR이 다뤄야 할 핵심 주제를 명확히 분리할 수 있다.
- 단점:
  - 구체적인 구현 기술 선택은 아직 확정되지 않는다.
  - 영속성, 재시도, 큐잉 방식의 운영 트레이드오프는 추가 결정이 필요하다.
